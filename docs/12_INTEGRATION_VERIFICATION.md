## 2. Protocol Analysis & Verification Details

### 2.1 INT-01: Frontend-to-Backend REST API Integration
- **Transport:** HTTP/1.1 over TCP.
- **Client Implementation:** Axios instance configured in `frontend/src/services/api.ts`.
- **Timeout:** Configured at $4000\text{ ms}$ (4.0 seconds).
- **Proxy Configuration:** `frontend/vite.config.ts` proxies routes (`/auth`, `/telemetry`, `/dashboard`, `/faults`, `/maintenance`, `/relays`, `/locations`, `/devices`, `/notifications`, `/audit`, `/health`) to `http://127.0.0.1:8000`.
- **Failure & Offline Behavior:**
  - If backend is offline or network fails, Axios requests catch errors and gracefully fall back to `generateSimulatedDashboard()`, ensuring the UI never crashes or displays white screens during demonstrations.
- **Identified Defect:** Production build uses `baseURL: ''`, requiring reverse-proxy routing unless `VITE_API_BASE_URL` is set.

---

### 2.2 INT-02: ESP32-to-Backend Telemetry Ingestion
- **Transport:** HTTP/1.1 POST to `/telemetry/`.
- **Payload Contract:** Pydantic schema `TelemetryCreate` in `backend/app/schemas/telemetry.py`.
- **Timing & Dual Timestamps:**
  - `sampled_at`: Generated at the edge by the hardware DS3231 RTC when electrical registers are latched.
  - `received_at`: Generated by FastAPI server via `datetime.now(timezone.utc)` upon request receipt.
- **Authentication:** Enforced via custom header `X-Ingest-Key`.
- **Identified Defect:** In `backend/app/core/security.py`, `require_ingest` raises HTTP 401 when an IoT device sends only `X-Ingest-Key` without a Bearer token. This is resolved by decoupling device key verification from user token validation.

---

### 2.3 INT-03: PZEM-004T Modbus RTU Protocol
- **Baud Rate:** 9600 bps (8 data bits, 1 stop bit, no parity).
- **Addressing:**
  - Phase R: Modbus Address `0x01`
  - Phase Y: Modbus Address `0x02`
  - Phase B: Modbus Address `0x03`
- **Register Read Command:** `0x04` (Read Input Registers).
- **Registers Read:** Voltage ($0.1\text{ V}$), Current ($0.001\text{ A}$), Power ($0.1\text{ W}$), Energy ($1\text{ Wh}$), Frequency ($0.1\text{ Hz}$), Power Factor ($0.01$).
- **Safety Boundary:** Microcontroller isolates each PZEM module's optical coupler to prevent mains cross-conduction.

## 3. Absence of Unnecessary External Dependencies

An audit of the repository confirms:
- **No External MQTT Broker Required for V1:** HTTP REST ingestion is simpler, reliable, and directly supported by FastAPI and ESP32 HTTPClient.
- **No Third-Party Cloud IoT Dependency:** The system is completely self-contained and operates on a private institutional LAN or internal server without requiring AWS IoT Core, Azure IoT Hub, or Google Cloud IoT.
- **No Unapproved Message Queues:** Standard PostgreSQL transaction queuing is sufficient for the institutional scale.
